# 模板驱动的新增记录与写回校验

F3/F4 的新增英雄和新增饰品不依赖当前存档中存在同类记录。空英雄名单、空饰品库存也必须可编辑。当前存档仍是其他未修改数据的事实来源；模板仅用于构造本次新增的完整 DSON 子树。

## 新增英雄

- `HeroFactory` 使用程序内置、版本化的 0 级空白英雄 DSON 模板，按当前有效内容环境填入职业、初始生命值和技能。缺少必需职业定义时拒绝创建，不从现有英雄克隆。
- 内置结构取自游戏初始远征中的十字军，因此新增到已有城镇时会把 `roster.status` 和 `roster.before_on_start_town_visit_status` 都设为 `0`。当前存档中的正常驻城英雄及已验证的新增英雄测试存档使用相同状态。经验、武器与防具原始等级为 `0`，技能原始等级为 `0`；初始生命值取职业定义的 0 级护甲生命值。洛琳 Mod 的该值是 `3`，属于职业定义，不能据此推断模板字段错误。
- Application 在 Session 中追加 `AppendTemplate` Operation；之后改名仍是独立的 `Hero.Name` Operation。新增与改名可分别撤销，保存时合并为同一候选存档。
- SaveAdapter 只把模板中的英雄对象追加到 `base_root/heroes/{guid}`。它同步推进 roster 的 `nextGuid`；写后校验从本次新增英雄的 ID 推导唯一允许的 `nextGuid` 值，并继续拒绝任何其他未映射字段变化。
- 现有英雄与本次新增英雄的名称都写在内嵌 DSON 的 `base_root/actor/name`。保存前仍要通过完整 Profile 备份、候选回读和目标指纹检查。

## 新增饰品

- 庄园饰品库存条目通过内置的固定字段结构创建，再用有效内容环境中的饰品 ID 填充 `id`。流程不查找或复制已有库存条目。
- 库存为空时仍使用相同的 `CreateObject` 和 `SetValue` 事务；批量新增、撤销、保存和备份沿用现有流程。

## 当前开放范围

英雄前端开放新增、改名、拖动排序和右键删除；Shift+右键跳过删除确认。删除仍执行后端的跨存档字符串引用检查。其他英雄属性暂不在 F3 开放。

回归测试覆盖空 roster 的新增后改名、空库存新增饰品、现有英雄改名提交，以及原有 SaveAdapter 和安全备份测试。上述测试验证编码、回读和差异约束；模板生成的新英雄仍需在游戏内完成对应职业和存档环境的验收。
